# Verify: Seller order panel · spec 0007 · updated 2026-11-08

_Steps derived from spec 0007 acceptance criteria. `/check verify` runs these; `/test` locks the durable ones._

Bring the dev stack up (`pnpm db:up`, `pnpm dev`) and switch the feature on: set `SELLER_ORDER_WORKFLOW_ENABLED=true` in `apps/api-astrum/.env` and restart the api process, because the flag is read once at boot. `API` is `http://localhost:3580/api`. `EMAIL` is an account that owns a business; hand it one with `pnpm db:assign-business $EMAIL` (the seeded catalogue leaves 21 unassigned businesses, so there is material to work with). `COOKIE` is that account's `__auth` cookie from devtools.

## UI / manual

_Walked on 2026-11-08 in the running storefront at `localhost:3000` against the gateway on `:3580`, signed in as a freshly registered and confirmed account that owned `biz_excel_4` (5 lines over 3 orders). Ticked steps were seen on screen. A second walk the same day, on a new account (`verify-seller-*`) given `biz_excel_10` by the operator script and 25 orders created through the buyer api, ran every step still owed below and closed them, except the loading strip of the pagination step, which failed there and was closed afterwards by a reproduction test (step 11). Three findings came out of that walk: a page change renders the skeleton instead of the rows with a thin strip (step 11); every product whose `previewImage` is the `placehold.co` placeholder rendered a broken thumbnail, because the optimizer rejects the SVG answer with `"url" parameter is valid but image type is not allowed` (4147 of 4747 products carry that placeholder, and an offline catalogue host answers `404` the same way), which the line row now avoids by sending an external source past the optimizer (`unoptimized`, as the cart card, the hero, the promo and the product gallery already do; `dangerouslyAllowSVG` stays off); and the keyboard walk could not be replayed in the headless browser, because `Tab` never moved focus, so focusability and the `focus-visible` ring were re-checked by focusing an action button instead (`:focus-visible` true, 32 px tall). The empty branch was closed too: a seller given `biz_excel_11` (237 products, no lines) read `Нечего собирать` / `Пока нет ни одного заказа со строками вашей лавки.` with no group and no pagination. Two layout defects were found in the first pass and fixed before it ended: the action column was an `auto` track, so the label row and a row carrying three buttons resolved to different widths and every column after it drifted; and a line with no action still rendered an empty actions band, which put a blank row under every finished line on mobile._
