# Astrum — ML-анализ отзывов

## What This Is

Интеграция ML-модели для анализа тональности отзывов о товарах в существующий интернет-магазин Astrum. Python-сервис на базе scikit-learn классифицирует отзывы как «Положительный / Отрицательный» и сохраняет результат. Секция отзывов отображается на странице товара на Next.js-фронтенде.

## Core Value

Каждый отзыв анализируется автоматически — пользователь и администратор сразу видят агрегированную тональность всех отзывов по товару.

## Requirements

### Validated

- ✓ Отзывы — модель в Prisma (таблица Review уже существует) — existing
- ✓ CRUD API для отзывов (`/api/reviews`) — existing
- ✓ Бэкенд Express + TypeScript — existing
- ✓ Фронтенд Next.js 15 — existing
- ✓ Auth-сервис NestJS — existing

### Active

- [ ] Фронтенд-секция отзывов на странице товара
- [ ] Python-сервис анализа отзывов (TF-IDF + Naive Bayes / логистическая регрессия)
- [ ] Интеграция: Express → Python сервис для классификации
- [ ] Визуализация тональности (положительный/отрицательный в UI отзывов)
- [ ] Агрегированная тональность по товару (средний рейтинг + соотношение позитивных/негативных отзывов)

### Out of Scope

- Обработка изображений в отзывах — нет данных, фокусировка на тексте
- Мультимодальные модели (BERT и т.п.) — TF-IDF + Naive Bayes достаточно для прототипа
- Модерация отзывов — не в рамках этого проекта
- Публичный API для ML — только внутренняя интеграция

## Context

Astrum — monorepo (Turborepo + pnpm). 4 приложения: API (Express), Auth (NestJS), Customer (Next.js), DB (Prisma). База данных PostgreSQL (Docker). Для ML нужен новый Python-сервис как отдельное приложение или пакет.

Датасеты: Kaggle Amazon Reviews, Ozon, IMDB.
Метрики: TF-IDF → Naive Bayes, логистическая регрессия.
Прототип: веб-форма ввода текста → модель возвращает классификацию.

## Constraints

- **Tech stack**: Python с scikit-learn (выбрано — не рассматриваем LLM-API)
- **Architecture**: Новый Python-сервис; Express вызывает его по HTTP
- **Данные**: Отзывы уже в Prisma, но Python нужна отдельная точка доступа — возможно, Prisma или прямое чтение из PostgreSQL
- **Совместимость**: Должно интегрироваться в существующий docker-compose

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Python-сервис отдельным приложением в monorepo | Изоляция ML-стека (scikit-learn конфликтует с pnpm/Node) | — Pending |
