# Система отзывов — Анализ фич

> Дата: 2026-04-04
> Контекст: Монополия Astrum (api-astrum, auth-astrum, customer), PostgreSQL + Prisma

---

## 1. Table Stakes (Обязательный минимум)

Без этих элементов система отзывов не может считаться полноценной. Оценка: **4/5** — покрывает ключевые ожидания рынка, редакция в v1 отсутсвует (осознанное ограничение).

| Фича | Описание |
|------|----------|
| **Рейтинг 1–5 звёзд** | Базовая оценка товара пользователем |
| **Текстовый отзыв** | Развёрнутый комментарий на странице товара |
| **Отображение на странице товара** | Отзывы видны внизу страницы товара (purchased → customer) |
| **Средняя оценка + распределение** | Агрегированный рейтинг и гистограмма (сколько отзывов на 1–5 звёзд) |
| **Привязка к покупке** | Только покупатель может оставить отзыв (link через Order → OrderItem) |
| **Имя автора и дата** | Каждый отзыв отображает имя пользователя и дату публикации |

## 2. Differentiators (Конкурентные преимущества)

Эти фичи выделяют систему отзывов среди типовых решений.

| Фича | Описание | Приоритет |
|------|----------|-----------|
| **Критериальные оценки** | Три отдельных рейтинга: качество товара, доставка, соответствие описанию | P0 (MVP) |
| **Фотографии в отзывах** | Пользователь может приложить фото полученного товара | P0 (MVP) |
| **Модерация перед публикацией** | Отзыв не появляется публично до одобрения модератором | P0 (MVP) |
| **ML-анализ тональности** | Автоматическая классификация:Positive/Negative (v1 — заглушка, v2 — модель) | P0 (MVP, заглушка) |
| **Ответ продавца** | Продавец может публично ответить на отзыв | P0 (MVP) |
| **Голосование «Полезно»** | Пользователи отмечают полезные отзывы, влияя на сортировку | P1 (Enhancement) |
| **Автоматические ML-теги** | Классификация отзывов по темам (брак, задержка, несоответствие) | P2 (Advanced) |
| **Расширенные фильтры** | Фильтр по звёздам, критериям, наличию фото, тональности | P1 (Enhancement) |

## 3. Anti-features (Осознанно исключённые)

Решения, которые **намеренно не входят** в объём v1.

| Anti-фича | Почему исключена | Когда пересмотреть |
|-----------|-----------------|-------------------|
| **Публикация без модерации** | Риск спама, нецензурного контента, фейков | Не в v1; возможно с ML-модерацией в v3 |
| **Редактирование/удаление отзыва** | Усложнение v1; может противоречить модерации | v2, после стабилизации потока |
| **Анонимные отзывы** | Подрывает доверие; у нас привязка к покупке | Не планируется |
| **Бесконечная прокрутка (infinite scroll)** | Усложнение; пагинация проще и прозрачнее | v2, при большом объёме отзывов |
| **Общий рейтинг без распределения** | Пользователю важно видеть разброс мнений | Не планируется — распределение обязательно |
| **Рейтинг без привязки к покупке** | Открыто для накруток; противоречит концепции verified buyer | Не планируется |
| **Авто-публикация на основе ML** | ML v1 — заглушка; нельзя доверять автоматическое решение | v3, когда ML-модель достигнет >95% точности |

## 4. Пользовательский путь (User Journey)

### Путь покупателя

```
1. Покупатель оформляет заказ
   ↓
2. Заказ переходит в статус «Доставлен» (delivered)
   ↓
3. На странице товара появляется кнопка «Оставить отзыв»
   (активируется при наличии OrderItem со статусом delivered)
   ↓
4. Покупатель заполняет форму:
   - Общий рейтинг (1–5 звёзд)
   - Качество товара (1–5)
   - Доставка (1–5)
   - Соответствие описанию (1–5)
   - Текстовый комментарий
   - Прикрепление фото (опционально, до N штук)
   ↓
5. Отправка отзыва → API создаёт запись со статусом "PENDING_MODERATION"
   ↓
6. Запускается ML-анализ тональности (v1 — заглушка)
   ↓
7. Отзыв ожидает модерации
   ↓
8. Модератор рассматривает и одобряет/отклоняет
   ↓
9. При одобрении → статус "PUBLISHED", отзыв появляется на странице товара
   При отклонении → статус "REJECTED", отзыв скрыт от публичного просмотра
```

### Путь продавца

```
1. Продавец видит новый ответ/отзыв в панели управления
   ↓
2. Может написать публичный ответ на отзыв
   ↓
3. Ответ публикуется без модерации (или с — по решению продукта)
   ↓
4. Ответ отображается под оригинальным отзывом на странице товара
```

### Путь модератора

```
1. Модератор видит очередь отзывов со статусом PENDING_MODERATION
   ↓
2. Просматривает текст, фото, ML-метку тональности
   ↓
3. Принимает решение: одобрить или отклонить
   ↓
4. При отклонении — указывает причину (опционально)
```

## 5. Паттерны модерации

### Паттерн A: Пре-публикация + ML-сортировка (Рекомендуется для v1)

```
Отзыв → ML-анализ (авто-классификация) → Очередь модератора → Решение → Публикация/Отклонение
```

- **Плюсы**: Полный контроль качества, ML помогает приоритизировать (спорные отзывы в начало очереди)
- **Минусы**: Задержка публикации, нагрузка на модератора
- **Подходит для**: Маркетплейсов с высокими стандартами качества контента

### Паттерн B: Полностью ручная модерация

```
Отзыв → Очередь модератора → Ручной просмотр → Решение → Публикация/Отклонение
```

- **Плюсы**: Максимальный контроль, нет зависимости от ML
- **Минусы**: Медленно, не масштабируется
- **Подходит для**: Малых объёмов (<50 отзывов/день)

### Паттерн C: Пост-публикация + жалуемый контент

```
Отзыв → Авто-публикация → Кнопка «Пожаловаться» → Модерация жалоб
```

- **Плюсы**: Мгновенная публикация, минимальные операционные затраты
- **Минусы**: Риск контента до модерации, зависит от активности сообщества
- **Подходит для**: Зрелых платформ с активным сообществом

### Рекомендация

**Для v1: Паттерн A** (пре-публикация с ML-ассистентом). ML-заглушка уже заложена в требованиях. С ростом объёма переходить к гибриду: доверенные продавцы → авто-публикация, новые/проблемные → ручная модерация.

## 6. ML-подходы к анализу тональности

### Уровень 1: Rule-based (v1 — текущий)

- Простая заглушка: Positive/Negative по наличию позитивных/негативных ключевых слов
- Или: Positive если рейтинг >= 3, Negative иначе
- **Сложность**: Низкая
- **Точность**: 60-75%
- **Инфраструктура**: Не требуется
- **Стек**: Чистый TypeScript/Node.js

### Уровень 2: Предобученная модель (v2)

- TF-IDF + Naive Bayes или логистическая регрессия
- Модель на Python/scikit-learn, обернутая в отдельный микросервис или вызываемая через subprocess
- Или: интеграция с готовым API (OpenAI, HuggingFace)
- **Сложность**: Средняя
- **Точность**: 80-90%
- **Инфраструктура**: Отдельный модуль или внешний API
- **Стек**: Python/scikit-learn ИЛИ готовый NLP API

### Уровень 3: Доменная специфическая модель (v3)

- Fine-tuned трансформер (RuBERT, ruRoBERTa) на данных Astrum
- Обучается на размеченных отзывах платформы
- Мультиклассовая классификация (positive/neutral/negative + аспекты)
- **Сложность**: Высокая
- **Точность**: 90-95%+
- **Инфраструктура**: Выделенный ML-сервис, пайплайн переобучения
- **Стек**: PyTorch/HuggingFace, ML pipeline

### Промежуточный вариант (рекомендуется между v1 и v2)

Использовать готовую библиотеку для анализа тональности русского языка (например, `compromise`-подобные решения или API) без собственной тренировки. Это даст 80%+ точности минимальными усилиями.

## 7. Модель данных

### Review

```prisma
model Review {
  id              String        @id @default(uuid())
  userId          String
  productId       String
  orderId         String
  orderItemId     String

  rating          Int           // 1-5 общий рейтинг
  qualityRating   Int           // 1-5 качество товара
  deliveryRating  Int           // 1-5 доставка
  accuracyRating  Int           // 1-5 соответствие описанию

  text            String        // текстовый комментарий

  status          ReviewStatus  @default(PENDING_MODERATION)
  sentiment       Sentiment     @default(UNKNOWN)  // Positive / Negative / Unknown

  photos          String[]      // массив URL фотографий

  publishedAt     DateTime?
  rejectedAt      DateTime?
  rejectionReason String?

  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt

  user            User          @relation(fields: [userId], references: [id])
  product         Product       @relation(fields: [productId], references: [id])
  responses       ReviewResponse[]

  @@index([productId, status])
  @@index([userId])
  @@index([orderId])
  @@index([status])
  @@index([sentiment])
}

enum ReviewStatus {
  PENDING_MODERATION
  PUBLISHED
  REJECTED
}

enum Sentiment {
  POSITIVE
  NEGATIVE
  UNKNOWN
}
```

### ReviewResponse

```prisma
model ReviewResponse {
  id        String   @id @default(uuid())
  reviewId  String
  sellerId  String   // или userId, если продавец = пользователь

  text      String   // текст ответа

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  review    Review   @relation(fields: [reviewId], references: [id], onDelete: Cascade)

  @@index([reviewId])
  @@index([sellerId])
}
```

### Требуемые изменения в существующей схеме

Связать с существующими моделями `User`, `Product`, `Order`/`OrderItem`. Убедиться, что `OrderItem` имеет статус `delivered` для валидации права на отзыв.

## 8. Карта зависимостей фич

```
[Order со статусом delivered]  ─┐
                                ├──→ [Оставление отзыва] ──→ [ML-анализ тональности]
[Product (существующий)]       ─┘                                    │
                                                                      ▼
[Модерация] ←────────────────────────────────────────────── [Review создан, статус PENDING]
    │                                                                 │
    ├─→ [Одобрено] ──→ [PUBLISHED] ──→ [Отображение на странице товара]
    │                                        │
    │                                        ├──→ [Средний рейтинг + распределение]
    │                                        ├──→ [Ответ продавца]
    │                                        └──→ [Фильтрация и сортировка]
    │
    └─→ [Отклонено] ──→ [REJECTED] ──→ [Скрыт, причина отклонения]
```

### Жёсткие зависимости (блокируют запуск)

| Зависимость | Зависит от | Тип |
|-------------|-----------|-----|
| Создание отзыва | Order Item со статусом delivered | Жёсткая |
| ML-анализ | Создание отзыва | Жёсткая (пусть заглушка) |
| Модерация | ML-анализ | Жёсткая |
| Отображение на странице | Модерация (статус PUBLISHED) | Жёсткая |
| Ответ продавца | Опубликованный отзыв | Жёсткая |

### Мягкие зависимости (улучшают, но не блокируют)

| Зависимость | Зависит от | Тип |
|-------------|-----------|-----|
| Распределение по звёздам | Отображение на странице | Мягкая |
| Голосование «Полезно» | Опубликованный отзыв | Мягкая |
| Фильтры отзывов | Отображение на странице | Мягкая |
| ML-теги | ML-анализ v3 | Мягкая |

## 9. Приоритизация по фазам

### MVP (v1) — Базовая функциональность

Цель: Пользователь может оставить отзыв, он проходит модерацию, появляется на странице товара.

| Фича | Компонент | Оценка (ч) |
|------|-----------|-----------|
| Prisma схема Review + ReviewResponse | @astrum/db | 1 |
| Эндпоинты CRUD для отзывов | api-astrum | 3 |
| Форма оставления отзыва | customer (Next.js) | 4 |
| ML-заглушка (sentiment) | api-astrum | 1 |
| Панель модерации | customer или отдельный UI | 3 |
| Отображение отзывов на странице товара | customer | 3 |
| Средний рейтинг + распределение | api-astrum + customer | 2 |
| Ответ продавца | api-astrum + customer | 2 |
| Привязка к покупке (валидация) | api-astrum | 1 |
| Загрузка фото к отзыву | api-astrum + customer | 3 |

**Итого MVP: ~23 часа**

### Enhancements (v1.5) — Улучшение UX

Цель: Улучшить качество отзывов и пользовательский опыт.

| Фича | Описание |
|------|---------|
| Голосование «Полезно» | Сортировка по полезности |
| Расширенные фильтры | По звёздам, критериям, фото, тональности |
| Сортировка отзывов | По дате, полезности, рейтингу |
| Агрегации по критериям | Средние значения для каждого критерия отдельно |
| Уведомления продавцу | О новом отзыве на его товар |

**Итого Enhancements: ~12 часов**

### Advanced (v2-v3) — Интеллектуальная система

Цель: Автоматизация и ML-обогащение.

| Фича | v2 / v3 | Описание |
|------|---------|---------|
| Предобученная ML-модель (TF-IDF + NB) | v2 | Замена заглушки на реальную модель |
| Доменная ML-модель (RuBERT fine-tune) | v3 | Высокая точность классификации |
| Автоматические ML-теги | v3 | Классификация по темам |
| Редактирование отзыва | v2 | Пользователь может править свой отзыв |
| Удаление отзыва | v2 | Пользователь может удалить свой отзыв |
| Авто-публикация доверенных | v3 | ML решает без модератора |
| Гибридная модерация | v3 | Комбинация ML + человек |

**Итого Advanced: ~30+ часов (растянуто на v2-v3)**

## 10. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|------------|---------|-----------|
| Низкий объём отзывов на старте | Высокая | Средняя | Стимулировать первые отзывы (email, бонусы) |
| Задержки модерации | Средняя | Средняя | Чёткие SLA, ML-ассистент для приоритизации |
| Фото не соответствуют товару | Средняя | Низкая | Модератор проверяет, авто-сжатие на клиенте |
| ML-заглушка неточна | Высокая | Низкая | Явная пометка «авто-анализ» + ручная модерация |
| Фейковые отзывы через обход валидации | Низкая | Высокая | Строгая привязка к Order + проверка статуса |
