# Шаблон тезисов для конференции

## 1) Параметры оформления в Word (по требованиям)

- Формат страницы: `A5` (`148 x 210 мм`).
- Поля: верхнее `20 мм`, нижнее `24 мм`, левое `19 мм`, правое `19 мм`.
- Шрифт: `Times New Roman`.
- Основной текст: `10 pt`.
- Подписи к рисункам, заголовки таблиц, текст таблиц, сноски, список литературы: `9 pt`.
- Абзацный отступ: `0,5 см`.
- Межстрочный интервал: одинарный.
- Нумерацию страниц не ставить.
- Формулы: через редактор формул, выравнивание по центру.
- Список литературы: по `ГОСТ 7.1-2003`.

## 4) Два режима наполнения текста

### Вариант A: краткий (быстрый, 2 страницы)

- Актуальность: 1 абзац.
- Цель и задачи: 4-6 строк.
- Методы и инструменты: 1 абзац.
- Основные результаты: 2-3 абзаца.
- Выводы: 3 пункта.
- Литература: 3-5 источников.

### Вариант B: расширенный (3-4 страницы)

- Актуальность: 1-2 абзаца с контекстом.
- Цель, задачи, объект, предмет: отдельными блоками.
- Методы: 1-2 абзаца.
- Результаты: 4-8 абзацев + 1 таблица или 1 рисунок (при необходимости).
- Выводы: 3-5 пунктов с практической значимостью.
- Литература: 5-10 источников.

## 5) Чек-лист перед отправкой

- Формат страницы точно `A5`.
- Поля выставлены: `20 / 24 / 19 / 19 мм`.
- Весь текст в `Times New Roman`.
- Размеры шрифта соблюдены: `10 pt` основной, `9 pt` подписи/литература.
- Абзац `0,5 см`, интервал одинарный.
- Номеров страниц нет.
- Название доклада отражает содержание и написано единообразно.
- Цель, результаты и выводы логически согласованы.
- В тексте нет пустых маркеров вида `[ВСТАВИТЬ ...]`.
- Источники оформлены по `ГОСТ 7.1-2003`.

`РАЗРАБОТКА МАСШТАБИРУЕМОЙ E-COMMERCE ПЛАТФОРМЫ ASTRUM НА БАЗЕ МОНОРЕПОЗИТОРИЯ`

**Актуальность.**  
Цифровизация торговли приводит к постоянному росту требований к интернет-магазинам: необходимы высокая скорость разработки, согласованность интерфейса и бизнес-логики, безопасная аутентификация пользователей и возможность масштабирования сервисов. Для учебных и стартап-проектов особенно важен подход, позволяющий одновременно ускорить разработку и упростить сопровождение. В этой связи актуальна реализация единой платформы, где клиентское приложение, API, сервис аутентификации и слой данных развиваются согласованно в рамках общего процесса сборки и поставки.

**Цель работы.**  
Цель работы - разработать и апробировать архитектуру e-commerce платформы Astrum с разделением на клиентский и серверные сервисы в монорепозитории, обеспечивающую удобство командной разработки и расширяемость функциональности.

**Задачи разработки.**  
1) Спроектировать структуру монорепозитория для совместной разработки фронтенда, API, auth-сервиса и базы данных.  
2) Реализовать клиентское приложение с основными пользовательскими сценариями каталога и корзины.  
3) Реализовать серверный API для работы с пользователями, товарами, избранным, корзиной и заказами.  
4) Организовать отдельный сервис аутентификации и безопасную проверку токенов на защищенных маршрутах.  
5) Настроить единый цикл запуска, сборки и проверки проекта.

**Объект и предмет.**  
Объект исследования - веб-платформа электронной коммерции.  
Предмет исследования - архитектурные и технологические решения, повышающие управляемость и расширяемость full-stack проекта.

**Методы и инструменты.**  
В работе применен инженерный подход к модульному проектированию программных систем. Проект реализован как монорепозиторий на базе Turborepo и pnpm workspaces. Клиентская часть построена на Next.js (React), серверная часть - на Node.js (Express/Nest-подход в сервисах), хранение данных и миграции организованы через Prisma и PostgreSQL. Для инфраструктурной переносимости использованы Docker и Docker Compose, для контроля качества - линтинг и типизация.

**Ход работы и основные результаты.**  
В рамках проекта сформирована структура Astrum с выделением отдельных приложений: `apps/customer` (frontend), `apps/api-astrum` (backend API), `apps/auth-astrum` (сервис аутентификации), а также пакета `packages/Astrum-db` для схемы данных и миграций. Такой подход обеспечил единые правила разработки и переиспользование инфраструктурных решений.

На уровне серверной части реализованы защищенные REST-маршруты для ключевых сущностей предметной области: пользователи, товары, избранное, корзина, заказы. Для разграничения ответственности auth-функциональность вынесена в отдельный сервис, к которому API обращается через проксирование запросов. Доступ к бизнес-маршрутам ограничен middleware проверки токена, что повышает безопасность обработки пользовательских действий.

На уровне клиентского приложения реализованы основные пользовательские сценарии интернет-магазина. В частности, в модуле корзины добавлена интерактивная карточка товара с управлением количеством, удалением позиции, работой с избранным и механизмом выбора/снятия выбора позиции. Это улучшает UX корзины и создает основу для дальнейших функций массовых операций над выбранными товарами.

Для ускорения командной разработки реализован единый набор скриптов запуска и обслуживания: общий dev-режим, отдельный запуск сервисов, операции работы с базой данных и контейнерами, а также централизованный линтинг и проверка типов. Практическим результатом стала согласованная среда разработки full-stack решения, уменьшающая трудозатраты на синхронизацию между участниками команды.

**Выводы.**  
1) Реализована рабочая архитектурная основа e-commerce платформы Astrum с разделением на frontend, API, auth-сервис и слой данных.  
2) Использование монорепозитория упростило сопровождение проекта, унифицировало процессы сборки и проверки качества, а также повысило скорость итераций команды.  
3) Реализованные функциональные модули, включая сценарии корзины и защищенные серверные маршруты, формируют базу для дальнейшего развития платформы (оформление заказа, аналитика, оптимизация производительности, расширение бизнес-логики).
